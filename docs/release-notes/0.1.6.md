## What's changed

### Fixed: the voice shortcut did nothing at all

LockIME takes over your voice key and sends it back to the input method. The key
it sent back was not an exact copy of the real one, so input methods did not
recognise it:

- **Right-hand modifiers lost their side.** A real keyboard marks right ⌥ (or
  right ⌘/⌃/⇧) as the *right* key; LockIME's copy only said "⌥", so an input
  method bound to right ⌥ never started recording. The copy now carries the same
  left/right and Fn markers as the hardware.
- **A lone modifier could not be recorded.** Voice keys are often a single key
  such as right ⌥, which the old recorder could not capture. Settings ▸ Voice
  Input has its own recorder again and accepts a single modifier. A key recorded
  in 0.1.4–0.1.5 is carried over automatically.
- **⌃⌥V swallowed every plain "v".** Modifiers now have to match exactly.
- **The key works right after you record it or grant Accessibility** — no
  relaunch needed.

### Changed: how the key behaves

- **Automatic switching off (the default):** LockIME now mirrors your key —
  down when you press it, up when you release it — so it works whether your
  input method toggles on a tap or records while the key is held. It no longer
  keeps its own idea of "recording", which could get out of step with the input
  method and, 60 seconds later, switch the microphone back on by itself.
- **Automatic switching on:** after you end voice input, LockIME waits 2 seconds
  for the recognised text to be inserted before switching back to your default
  input source. The safety timeout now only switches the source back; it never
  presses the key for you.

### New: the menu shows which input source is selected

The locked input source has a checkmark (drawn by macOS itself, so it shows on
every macOS version) and a filled pin. A default source that is not being
enforced because LockIME is off shows an outline pin.

### Faster and lighter

- The voice key is handled on its own thread, so typing in other apps is never
  held up by LockIME's main thread.
- Fewer background wake-ups: password-field (secure input) checks slow down after
  10 seconds, rapid app switching is handled once, and launcher (Spotlight,
  Raycast) notifications are coalesced and ignored while LockIME is off.
- With per-URL rules on, the browser's URL is read far more cheaply, the check
  pauses while the display sleeps, and nothing is read while LockIME is off.

## Before you use it

- **Grant Accessibility again.** This build has a new ad-hoc signature, so macOS
  no longer recognises the previous grant. In **System Settings ▸ Privacy &
  Security ▸ Accessibility**, remove the old LockIME Voice entry if it is listed,
  then add this one.
- **Check your voice key** in **Settings ▸ Voice Input**. If it is empty or
  wrong, click the field and press the same key your input method uses for voice
  input (for example right ⌥).
