## What's changed

### One permission instead of two

Settings ▸ Permissions used to show a second **Event Posting** section asking for
"permission to send keyboard events". It could not be granted, because it is not a
separate macOS permission: sending the voice key and taking the voice key over are
the same **Accessibility** grant. Earlier builds also asked for **Input
Monitoring**, which this workflow never uses — LockIME takes one key over, it does
not listen to what you type.

Both are gone. The Permissions pane lists Accessibility only, and the voice input
pane points at that same single grant.

### Upgrade note

The installers are ad-hoc signed, not notarized, so macOS treats every update as a
different app:

- **Grant Accessibility again after updating** (System Settings ▸ Privacy &
  Security ▸ Accessibility). If "LockIME Voice" is listed twice, the entry whose
  switch will not stay on belongs to the previous build — remove it with `−`, then
  enable the one you just installed.
- If an entry for LockIME Voice is sitting in **Input Monitoring**, it comes from
  an earlier build; this version never asks for it and you can remove it.
