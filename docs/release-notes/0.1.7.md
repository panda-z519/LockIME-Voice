## What's changed

### Fixed: typing now ends voice input — and hands your text input back

Until now a voice session ended only when you pressed the voice key again, or
after the 60-second safety timeout. If the voice input method never started
recording — no microphone, or its microphone permission denied — you were left on
the voice input source with no quick way back to typing.

The first keystroke now ends the session and hands the input source straight back
to the layout you type in, so the character you just typed lands where you expect.
The keystroke itself is never swallowed. Ending this way sends **no** "stop
recording" key: a blind toggle would restart a recording the input method had
already stopped by itself, and there is nothing to stop when it never started.

### Fixed: the same now works when the voice key is a lone modifier

Voice keys are often a single key such as right ⌘ or right ⌥. The previous build
only watched for typing when the voice key was a full combination like ⌃⌥V, so a
lone modifier still ran until the timeout. Both shapes now behave identically.

Pressing the voice key again still ends the session as before.

### Fixed: the permission the workflow needs can now actually be granted

LockIME only *checked* whether macOS allowed it to send keystrokes; it never
*asked*. An app that never asks is not listed in **System Settings ▸ Privacy &
Security ▸ Accessibility**, so there was nothing to switch on — the toggle either
did not exist or appeared already enabled and did nothing.

The grant buttons now request the permission through macOS, so LockIME Voice is
listed and the switch takes effect.

### Upgrade note

The installers are ad-hoc signed, not notarized, so macOS treats every update as a
different app:

- **Grant Accessibility again after updating** (System Settings ▸ Privacy &
  Security ▸ Accessibility). If "LockIME Voice" is listed twice, the entry whose
  switch will not stay on belongs to the previous build — remove it with `−`, then
  enable the one you just installed.
- Right after an update, the first voice key press may ask for permission once
  more.
