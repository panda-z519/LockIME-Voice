## English

### What's changed

#### The voice key actually wakes the voice input method now

With **Switch input source automatically** on, every press of the voice key
switched to the voice input method and straight back, and voice input never
started. LockIME checked the "post keyboard events" permission with an API whose
answer is cached when the app launches, so a launch before Accessibility was
granted kept reporting "denied" for good — even though macOS was already allowing
the key. LockIME now checks the live Accessibility grant: once you grant it, the
voice key works without relaunching the app.

#### Back to the input source you were using

When voice input ends, LockIME now switches back to the input source that was
active **when you pressed the key** — not to the global default from App Rules.
The global default is only a fallback, so you no longer have to set one before
using automatic switching. Pressing the key while you are already on the voice
input method just passes the key on, without switching anything.

#### Tap or hold — both work, no setting needed

- **Tap** the voice key to start, tap it again to stop.
- **Hold** it while you speak (half a second or longer) and release to stop.

Either way LockIME waits a moment for the text to be committed, then switches
back. The wait for a voice input method that is not running yet was also raised
from 0.5 s to 1.5 s, so a cold start is no longer treated as a failure.

#### Any other key ends voice input — without losing the text

Typing during voice input used to switch back at once while the voice input
method was still recognizing, and the key you pressed replaced the recognized
text. Now any other key ends voice input exactly like pressing the voice key
again: the key is swallowed (it is not typed), the recognized text is kept, and
the input source is switched back.

#### A left/right modifier means that side only

A bare modifier voice key such as **right ⌘** used to trigger from either side.
It now triggers only on the side you recorded; the other side is an ordinary
modifier again.

### Upgrade note

- **Grant Accessibility again after updating** (System Settings ▸ Privacy &
  Security ▸ Accessibility). The installer is ad-hoc signed, so macOS treats it as
  a different app. If "LockIME Voice" is listed twice, remove the old entry with
  `−` and enable the one you just installed.
- If your voice key is a bare modifier, check in **Settings ▸ Voice Input** that
  it shows the side you actually press (for example "Right ⌘"). It used to work
  from both sides, so a key recorded on the wrong side went unnoticed; re-record
  it if needed.
- Settings ▸ Voice Input no longer shows a **Restore input source** row, and no
  longer asks you to set a global default first.

## 简体中文

### 更新内容

#### 语音键终于能真正唤醒语音输入法

开启「自动切换输入法」时，以前每按一次语音键，都会切到语音输入法又立刻切回来，语音
始终没有启动。原因是 LockIME 检查「发送键盘事件」权限用的接口，会在 App 启动时缓存
结果：只要启动时还没授予辅助功能，之后就一直判定为「拒绝」，哪怕 macOS 早已允许发键。
现在改为实时检查辅助功能授权，授权后不用重启 App，语音键就能直接用。

#### 切回你原来在用的输入法

语音结束后，LockIME 现在会切回你**按下快捷键那一刻**正在用的输入法，而不是 App Rules
里的全局默认。全局默认只作兜底，所以使用自动切换前不再需要先设置它。如果按键时已经在
语音输入法里，就只把按键转发过去，不做任何切换。

#### 按一下、按住都行，不用设置

- **按一下**语音键开始，再按一下结束；
- **按住**说话（半秒以上），松开即结束。

两种方式结束后，LockIME 都会稍等片刻让文字上屏，再切回去。等待尚未运行的语音输入法
启动的时间也从 0.5 秒放宽到 1.5 秒，冷启动不会再被误判为失败。

#### 按其他键结束语音，文字不再丢

以前在语音进行中打字，会在语音输入法还在识别时立刻切回，按下的键还会把已识别的文字
覆盖掉。现在语音中按任意其他键，效果和再按一次语音键一样：这个键会被吞掉（不会打出来），
已识别的文字保留，然后切回原来的输入法。

#### 左右修饰键只认录入的那一侧

单独修饰键作语音键（例如**右 ⌘**）时，以前左右两边都会触发。现在只有录入的那一侧会
触发，另一侧恢复成普通修饰键。

### 升级须知

- **更新后需要重新授予辅助功能**（系统设置 ▸ 隐私与安全性 ▸ 辅助功能）。安装包是
  ad-hoc 签名，macOS 会把它当成另一个 App。如果「LockIME Voice」出现两条，用 `−` 删掉
  旧的那条，再打开刚安装的这条。
- 如果语音键是单独的修饰键，请在 **设置 ▸ 语音输入** 里确认显示的是你实际按的那一侧
  （例如「右⌘」）。以前左右都能触发，录错了一侧也察觉不到；需要的话重新录一次。
- 设置 ▸ 语音输入 不再显示「恢复输入源」一行，也不再要求先设置全局默认输入法。
