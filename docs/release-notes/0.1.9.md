## What's changed

### The installer now tells you how to open it

These builds are ad-hoc signed and not notarized, so the first launch is refused
with *“Apple could not verify “LockIME Voice” is free of malware”* — which reads
like a corrupt download, and most people stop there.

The disk image now carries a short bilingual note, right beside the
drag-to-Applications target, saying what to do:

- drag **LockIME Voice** onto **Applications**;
- when macOS refuses to open it, go to **System Settings ▸ Privacy & Security ▸
  Security** (bottom of the page) and click **Open Anyway**, then confirm;
- the voice shortcut needs exactly one permission — **Accessibility**. Input
  Monitoring is not needed: LockIME never listens to your typing.

No application code changed in this release; it is the same 0.1.8 behaviour with a
self-explaining installer.

### Upgrade note

Because each installer is ad-hoc signed, macOS treats it as a different app:

- **Grant Accessibility again after updating** (System Settings ▸ Privacy &
  Security ▸ Accessibility). If "LockIME Voice" is listed twice, the entry whose
  switch will not stay on belongs to the previous build — remove it with `−`, then
  enable the one you just installed.
