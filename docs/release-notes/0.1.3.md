## What's changed

### Fixed: the shortcut-conflict prompt is gone

The voice workflow no longer shares one shortcut with your input method. Through
v0.1.2 you recorded a single key — the input method's own voice key — and LockIME
both **listened for** it and **sent it again**. One press was handled twice, and
for keys macOS reserves for itself (Fn/🌐) macOS or the input method reported a
**shortcut conflict** on every activation.

This build splits the two, so each key is handled exactly once:

| Shortcut | Where you set it | What handles it |
|---|---|---|
| **LockIME voice shortcut** | Settings ▸ Voice Input (or Settings ▸ Shortcuts) | LockIME, once |
| **Input method voice shortcut** | inside your input method | your input method |

**You must do this once after upgrading:** record your LockIME voice shortcut. It
is a new, separate key and has no previous value to carry over. The pane warns
you, and also warns if you accidentally set both to the same combination. The
input method's voice key you already configured keeps working and does not need
re-recording.

### New: switching the input source is now optional

**Switch input source automatically** is off by default. With it off, the
synthesized shortcut alone starts voice input in whichever input method is
active, and your input source is never touched. Turn it on if the voice input
method is not the one you normally type in: LockIME then switches to it, sends
its voice key, and restores your global default source afterwards.

If you are upgrading and the workflow used to switch sources, that behavior is
preserved: a stored configuration decodes with switching still on.

### Changed: fewer permissions and fewer behaviors

- **Input Monitoring is no longer needed.** LockIME only *sends* the voice key
  now, so it never listens for your typing. Only the "send keyboard events"
  permission is requested (the same System Settings page grants it).
- **Hold to speak and "any key to end" are no longer offered.** Both need a key
  listener, which is exactly the mechanism that caused the conflict. Press once
  to start, press again to end.

### Changed: DMG packaging

The preview app no longer ships as a debuggable build. Ad-hoc signing was making
Xcode inject `com.apple.security.get-task-allow` — the flag that permits
attaching a debugger — and it is gone from the installers. Hardened Runtime is
unchanged.

## Install

Ad-hoc signed and **not notarized**. The first launch is blocked by Gatekeeper:

1. Double-click **LockIME Voice**. macOS refuses it with *"Apple could not verify
   that LockIME Voice is free of malware"* — expected, not a broken download.
2. Open **System Settings ▸ Privacy & Security** and scroll to **Security**.
   **LockIME Voice** is listed with an **Open Anyway** button.
3. Click **Open Anyway**, authenticate, then confirm with **Open**.

After launching, grant **Accessibility** when asked (the voice workflow needs it;
sending keyboard events is granted from the same dialog).
